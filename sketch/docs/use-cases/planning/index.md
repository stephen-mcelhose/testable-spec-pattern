# Planning

> [!WARNING]
> PLACEHOLDER: No planning skills exist yet. Industry-standard planning tools and approaches apply given good inputs.

The planning phase produces an ordered implementation approach — informed by [Requirements](../requirements-gathering/requirements.md) and [Contracts](../contracts-and-domain-modeling/contracts.md), before implementation begins.

## Use Cases

### Plan from Requirements

As a software engineer, I want to [Plan](../planning/index.md) a new feature from [Requirements](../requirements-gathering/requirements.md) in order to inform [Implementation](../implementation/index.md) of software.

### Plan from Requirements and Contracts

As a software engineer, I want to [Plan](../planning/index.md) a new feature from [Requirements](../requirements-gathering/requirements.md) and [Contracts](../contracts-and-domain-modeling/contracts.md) in order to produce an ordered implementation approach that informs [Implementation](../implementation/index.md) of software.

> [!NOTE]
> Planning is distinct from domain modeling. Domain modeling names the things and shapes the contracts; planning decides the order and approach for building against them.
